## What got built — the dual-design pattern, proven

This is the session that proves the architecture you locked in earlier. One brief, two lenses, with the gap surfaced honestly.

### `components/c02/branched_checks.py` (new, ~350 lines)

Three functions wired together as a single conceptual check:

**`check_setback_compliance_practical(brief)`** — validates against the user's stated setbacks. Accepts user-chosen compromises. Only fails on physical impossibility (negative setbacks, envelope below 1×1m).

**`check_setback_compliance_code_strict(brief)`** — validates against NBC/DCR-mandated setbacks. HARD_FAILs whenever user-stated < NBC on any side. Reports per-side violations with shortfall_pct.

**`compute_setback_gap(brief)`** — produces a `Gap` if and only if the two variants disagree. Severity from worst-side shortfall:
- < 15% short → `MARGINAL`
- 15-30% short → `SIGNIFICANT`
- ≥ 30% short → `BLOCKING_IF_NOT_ACCEPTED`

When user-stated == NBC on all sides → `compute_setback_gap` returns `None` (the "got lucky" case).

|---|---|---|---|

| 0.9 all sides (40% short) | PASS | HARD_FAIL | BLOCKING_IF_NOT_ACCEPTED |
| 0/0/0/0 (illegal) | PASS (envelope OK) | HARD_FAIL | BLOCKING |

**`InputField[T]` generic dataclass** — wraps any value with provenance. `__post_init__` enforces invariants: VERIFIED/UNVERIFIED MUST have non-None value; DOESNT_KNOW/NOT_ASKED MUST have None. Builders: `InputField.verified(...)`, `.unverified(...)`, `.unknown()`, `.not_asked()`.

**`FeasibilityInput`** — wraps the Brief plus 6 optional InputFields (soil, water table, electric line distance, electric line type, water course distance, water course presence). All default to NOT_ASKED.

**Auto-mapping properties** — `confidence_level` and `verification_priority_for_value` derived from source.

## The downgrade rule, proven end-to-end

User explicitly approved: *"Assumed values that would HARD-fail → soft-warn"*. This is now real, tested behavior:

| Scenario | Source | Raw severity | Final severity |
|---|---|---|---|
| Pune G+3 + don't-know | NOT_ASKED | HARD_FAIL | **SOFT_WARN + assumption disclosed** |
| Pune G+3 + verified black_cotton | VERIFIED | HARD_FAIL | **HARD_FAIL preserved** |
| Pune G+3 + unverified black_cotton (user's guess) | UNVERIFIED | HARD_FAIL | **HARD_FAIL preserved** |
| Chennai G+1 + don't-know | NOT_ASKED | SOFT_WARN | SOFT_WARN (no change — already soft) |

**The key distinction:** the user's data — even unverified — counts as theirs. They get a strict warning. A system-default guess never gets to block them.

When downgrade fires, the message includes a clear note: *"Severity downgraded from HARD_FAIL to SOFT_WARN because the value used was a city-default assumption, not user-verified data. Get site-specific verification to confirm."* And `verification_priority` becomes CRITICAL.

## Honesty notes

### RWH check rules legally accurate

These thresholds came from the actual legislation, not guesses:

- BWSSB Act amendment 2009 (Bangalore 111 sqm)

### Approval complexity tiers are heuristic

The simple/medium/complex breakdown comes from researching typical timelines from BBMP, CMDA, MCGM official portals (cited in `_meta.source_standards`). **Real timelines vary 50-100% based on document quality, officer responsiveness, and NOC delays.** The check is INFO-only specifically because predicting exact timelines is impossible — we set realistic expectations rather than pretend to know.

### Cross-city RWH cost is broadly representative

`RWH_COST_RANGE_LAKHS = (0.5, 2.0)` is industry-typical for residential plots based on builder quotes. Could be lower (₹30K for very basic) or higher (₹3L+ for filtration + storage tank), but the range covers ~80% of cases. **Logged for v0.2 refinement based on real builder data if available.**
