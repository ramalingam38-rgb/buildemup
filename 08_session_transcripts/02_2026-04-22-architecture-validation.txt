## The working-vs-regulatory-drawing question — properly treated

You're correct this is not a rendering concern. It's a foundational architecture concern. Two different setback regimes produce two different feasibility outcomes, and the engine must handle both honestly.

| | Working drawing | Regulatory drawing |
|---|---|---|
| Purpose | What gets built | What gets approved |
| Setbacks | User's preferred (often 1.5–2ft in urban Indian reality) | NBC / CMDA / city-mandated (5/3/3 for Bangalore, varies by plot size for Chennai) |
| Who sees it | Contractor, user, BOQ | Planning authority, approval submission |
| What the BOQ is based on | This one | Not this |

What this means for the architecture is concrete:

Feasibility (Component 2) runs **twice** — once with working setbacks, once with regulatory setbacks. The output is a pair of reports, not one.

Placement (Component 11) produces **one** layout, but it is evaluated against both setback regimes. A layout that passes working but fails regulatory gets a prominent warning ("this will require a site adjustment or a setback variance for approval").

The renderer (Component 18) produces **two drawings** from the same room data, with the setback lines and dimensions labelled accordingly. Same house, two presentations.

The honest cases the engine has to handle:
- Both pass → normal output
- Working passes, regulatory fails → produce both, flag clearly, explain what needs to change for approval
- Regulatory passes, working fails → unusual, means the user's preferred setbacks are *looser* than NBC, which is suspicious — flag for review
- Both fail → back to trade-off negotiation

## Your "identify all the problems" mandate

You said: "We need much better engine that can identify all the problems in the layout."

This reshapes Component 15 significantly. The Lived Quality Scorer is not a single number — it's a **structured problem report**. Roughly 30–40 specific checks across 8 categories. Every check returns status (pass / warn / fail), severity (critical / high / medium / low), plain-English explanation, and a suggested fix. The user sees a report, not a score.

| Category | Example checks |
|---|---|
| Privacy | Bedroom visible from entry; WC visible from dining; master wall adjoins guest bedroom; line-of-sight from front door into private zone |
| Light | Living not on north face; bedroom on harsh west face; kitchen has no east/north window; any habitable room with no external wall |
| Ventilation | Any room with no opening to outside air; kitchen sharing wall with bedroom; bathroom with no vent shaft; stack effect blocked |
| Circulation | Bedroom is a transit room; corridor >15% of floor area; path requires >2 turns to reach bedroom from entry; pinch point <3ft |
| Furniture fit | Bed + wardrobe don't fit; dining table blocks a door swing; kitchen work-triangle too long; bathroom too narrow for basin+WC+shower clearance |
| Structural | Column inside a room; wall off-grid by more than 6"; bathroom not vertically aligned with kitchen/other bath; staircase doesn't stack |
| Regulatory | NBC room minimum violated; FAR exceeded; front/side/rear setback short; parking missing or under-sized; rainwater sump absent in mandated states |
| Proportion | Room aspect ratio >1:2.5 (feels like a corridor); orphan L-corner under 15 sqft; dead-end corridor; no focal wall in living room |

This is the single most valuable deliverable BuildemUp produces beyond the layout itself. No Indian competitor does this. Contractors certainly don't. A per-layout problem report is a moat on its own.
