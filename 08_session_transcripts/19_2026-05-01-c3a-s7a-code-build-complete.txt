### Phase 2 — `api/c3a_endpoint.py` build (~1455 LOC final)

The big piece. Spec § 5 defines 5 handler signatures, each
`def handle_X(request_body: bytes | str) -> tuple[int, dict]`. Pure
handlers — no networking; `api/server.py` routes URLs to them.

Architecture:
- Module-level lazy storage singletons (`_storage`, `_brief_storage`)
  with `reset_storages_for_tests` setter for test isolation.
- Production C2 runner wraps `c02.orchestrator.run_feasibility`.
  `_make_gate(c2_runner=None)` factory for handler use; tests inject
  via patching `_make_gate`.
- Hook injection via module attributes `_send_cba_checklist` and
  `_schedule_fallback_invitation`, bound at import time to the v0.1
  stubs. Tests override these directly for counter-based fakes.
- Helpers: `_parse_and_size_check` (P9 + § 6.1), `_require_str` for
  field validation, `_error_response` for structured 4xx, `_wire_aborted`
  / `_wire_paused` for P7 normalization.
- Response builders: per-endpoint, branching by termination reason
  for /resolve (the most complex — 6 terminal paths + continuing
  + Branch C error).
- `_add_24h_iso(iso_ts)` for fallback_at computation; permissive
  recovery on parse failure (informational field).

P-invariants enforced:
- **P9 / § 6.1**: `_parse_and_size_check` runs FIRST in every handler;
  body size cap, JSON parse, top-level dict shape check.
- **P18**: per-field validation runs after JSON parse, accumulating
  structured errors before returning 400.
- **P12**: `/check` calls `lookup_brief_session` first; on hit, replays
  cached response (with terminal-replay advisory if state.is_done).
  On miss, generates fresh session_token, runs gate.start, saves,
  then `register_brief_session` claims uniqueness. Lost-race path
  resumes the winner's response.
- **P11**: every mutating handler wraps read→compute→save in
  `with get_session_lock(token):`.
- **P2**: idempotency replay checked AFTER lock acquisition but
  BEFORE the P3 terminal check (per § 5.2 ordering).
- **P3 + P15**: terminal token returns 200 with cached response +
  `session_status: "terminal_replay"` advisory.
- **P10**: `storage.save_existing(...)` happens FIRST; hooks fire
  AFTER (best-effort, swallowing exceptions per § 7.4 hook contract).
- **P13**: `save_existing` already implements atomic state+cache
  co-write at the storage layer; handler just calls it.
- **P7**: every terminal response sets `is_done=True` plus
  `aborted=_wire_aborted(state)` and `paused=_wire_paused(state)`
  supplementary flags for client convenience without mutating S6
  semantics.
- **P16**: hooks NOT re-fired on idempotency replay because the
  P2 short-circuit returns the cached response BEFORE reaching
  the hook-fire block.

Branch C (BriefChangeIntegrityError) returns HTTP 200 with
`last_error_message` + `last_error_option_id` + `failed_option_ids_for_current_case`
fields per § 6.2 (locked Decision § 9.34).

#### test_c03a_session7_api_endpoints.py (28 tests)

`_EndpointTestBase` setup: isolated tempdir storages, fake C2 runner
via `_make_runner`, no-op hook stubs (default; tests that observe
hooks override directly), `_make_gate` patched to inject the fake
runner.

Coverage by endpoint:
- /check (8 tests): no-blockers terminal SUCCESS, with-blockers
  continuing, unknown brief_token → 410, malformed JSON → 400,
  missing request_id → 400, oversize body → 400 (P9), idempotency
  same brief_token + request_id returns same session_token (P12)
- /resolve (10 tests): terminates with SUCCESS, continues to next
  case, pauses for CBA verification, unknown session_token → 410,
  terminal token → 200 with cached + advisory (P3 + P15), invalid
  option_id → 400, missing user_acknowledged_at → 400, missing
  request_id → 400 (P2 — server doesn't auto-generate), duplicate
  request_id replays cached (P2), oversize body → 400 (P9)
- /abort (3 tests): records decision_log + USER_ABORTED, terminal
  → 200 with cached + advisory (P3 + P15), duplicate replay (P2)
- /cba-verified (5 tests): CBA_CONFIRMED → restart instruction,
  NOT_CBA → proceed-with-original, STILL_UNSURE → manual followup,
  unknown verification_result → 400, non-paused mid-flow → 409
- /cba-fallback-continue (2 tests): resume with DETACHED assumption,
  non-paused mid-flow → 409
- TestSingleFlightLock (1 test, P11): two threads /resolve
  concurrently. Lock proof: exactly one 200 (winner) and one 400
  (loser, with stale case_id post-mutation). Final iteration_count
  == 1, proving no lost-update.

The single-flight test was the one that needed iteration. First
attempt expected 2× 200 with iteration_count == 2, which would have
required different case_ids per thread — but the test setup had
both threads target the same head case. After the first /resolve
advances the head, the second thread sees a different head and
correctly rejects the stale case_id with 400. Reframed the test to
assert THIS pattern (one winner + one stale-rejection with explicit
"case_id mismatch" check) which actually proves the lock's value
better than 2× success would — without the lock, both could have
committed concurrent state mutations producing inconsistent
iteration_count.

### Phase 6 — Bug discovery: B-043

`test_save_existing_unknown_token_raises` (initial draft) revealed
a real bug in `gate_state_storage.save_existing`: when UPDATE finds
rowcount=0, the error path manually rolls back the transaction, then
raises TokenNotFoundError. The outer `except Exception` clause then
attempts a SECOND rollback which fails with `sqlite3.OperationalError:
cannot rollback - no transaction is active`, masking the original
TokenNotFoundError. Per the handoff DO-NOT-MODIFY rule for the
storage layer, the test was REMOVED and a backlog item B-043 logged
for S7b or a dedicated mini-fix session. The code-comment above the
removed test explains the situation for future readers.

### Phase 7 — Code-critique pass (D-066 step 7)

8 findings, severity-ordered:

- **C1** (low): `_summarize_brief` uses `:g` formatting; integer-float
  dimensions like 10.0 display as "10". Acceptable.
- **C2** (low): `_compute_applied_changes` returns empty tuple if

  is informational only.
- **C3** (low): `_add_24h_iso` returns input unchanged on parse
  failure. UI handles; informational field.
- **C4** (medium-but-not-fix-worthy): two concurrent /check calls with
  same (brief_token, request_id) may both reach gate.start before
  register_brief_session resolves the race. Loser's gate_state row is
  wasted but P12 logical uniqueness holds. Inefficient under load,
  not a correctness bug. Backlog candidate (NOT added; documented
  here for S7b consideration).
- **C5** (low): module-level storage singletons reset to None in
  tearDown — lazy re-init creates a default. Verified safe.
- **C6** (medium, FIXED): `_build_resolve_response` was passing
  `email_sent_to=None` even though `new_state.current_brief.user_email`
  was available. Pattern B risk (built but not fully wired). Applied
  the fix.
- **C7/C8** (low): defensive 500 paths for unreachable states
  (USER_ABORTED in /resolve terminal builder, missing terminal
  cache). Acceptable defensive code.
