## Structural drawbacks — my honest take

### 1. SCWB is oversimplified

**The critique is correct.** Real strong-column-weak-beam needs moment capacities (which depend on reinforcement layout), not just dimensions. My current check is `column_size_mm / beam_depth_mm ≥ 0.6` — that's a heuristic, not engineering.

**My reaction:** I should not pretend it's more than that. Two fixes:
- Rename internally to `scwb_heuristic_check` (not `scwb_check`)
- The output should explicitly say "Heuristic only — actual SCWB requires moment capacity calculation by engineer"
- The seismic reliability score should NOT use this check as a strong signal — only as a weak signal

**Effort:** 1-2 hours. **Verdict: must do.**

### 2. No frame analysis

**Correct, and I'd push back partially.** For G+1/G+2 residential with brick infill, IS 1893 cl. 7.10.3 explicitly permits skipping frame analysis. So we're code-compliant. But the critique's real point is: **we should say so.** Right now we silently skip it; we should explicitly disclose.

**Effort:** 1 hour to add explicit disclosure. **Verdict: must do.**

### 3. Wind + seismic not combined

**Correct.** IS 875 has load combinations like `1.5(DL+LL+EQ)` and `1.2(DL+LL+EQ+WL)` — you check both and use the worse one. I'm computing wind separately and not comparing it to seismic.

**Honest assessment:** For G+2 residential in Zone III+, seismic always governs over wind (per Murty, ch. 6). For Zone II coastal G+4, wind may govern. So in practice this rarely changes the answer.

**Fix:** Add a load-combination function that explicitly compares and picks the worse one. Even if it almost always picks seismic, the user sees we checked.

**Effort:** 2-3 hours. **Verdict: must do.**

### 4. Pile foundation is conceptual

**Correct.** I have catalog values for pile capacity but no skin-friction-vs-end-bearing breakdown, no group settlement, no pile-soil interaction.

**My honest view:** Real pile design is geotechnical engineering — multiple weeks of work and requires soil test data we don't have. What I should do:
- Be more explicit that pile output is "preliminary sizing for cost estimation only"
- Add a line in pile output: "Pile design must be confirmed by geotechnical engineer with soil test data"
- NOT add fake skin-friction calculations using assumed soil parameters (that would be MORE dangerous, not less)

**Effort:** 1 hour for disclosure. **Verdict: do disclosure, defer real geotech to v2.**

### 5. Regularity check is binary

**Correct.** Right now: regular OR irregular. Reality: degree of irregularity matters. A 16% re-entrant corner is barely irregular; a 40% corner is severely irregular.

**Fix:** Three levels (REGULAR / MODERATELY_IRREGULAR / SEVERELY_IRREGULAR) with different responses:
- REGULAR → proceed normally
- MODERATELY_IRREGULAR → warn, allow proceed
- SEVERELY_IRREGULAR → refuse, require expert review

**Effort:** 2 hours. **Verdict: must do.**

### 6. No beam design logic

**Partially correct, partially over-scoped.** Beam moment calculation is detailed structural design, not preliminary sizing. We size beams by span/12 (Devdas Menon heuristic) which is conservative.

**My honest view:** Same as P-M curves — this belongs with the structural engineer at detailed design. We should disclose, not add fake calculations.

**Effort:** 1 hour for disclosure. **Verdict: disclose, defer to v2.**

### 7. No serviceability checks

**Partially correct.** Deflection limits are usually satisfied automatically when span/depth ratios are met (which our beam sizing does). Crack width is detailed design.

**My honest view:** Disclose that we don't check these explicitly. **Verdict: disclose only.**
