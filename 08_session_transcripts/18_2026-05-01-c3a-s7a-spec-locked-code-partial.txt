In two messages Ramalingam established:

RULE 1 — Handoff is a single integrity-checked zip file:
  - Contains everything from previous handoff zip

    + audit check (all session artifacts included) reported BEFORE
    delivery

RULE 2 — Latest-only delivery + spec self-containment:
  - Spec patches: deliver only the latest file (v0.3 only, not v0.1
    + v0.2 + v0.3)
  - Spec backlogs: items deferred during critique rounds documented
    INSIDE the spec file, not just in the project backlog (so the
    spec is self-contained)
  - Code files: delivered consolidated (single .py with module
    boundary headers, the way S6 was)

RULE 3 — Chronological order + actionable next-Claude instructions:
  - Conversations and files inside the zip organized in chronological
    creation order so the next Claude reads the process linearly
  - Handoff specifically tells the next Claude WHAT TO DO with
    concrete actionable detail (not just orientation)

EVENT 10b — Ramalingam added Rule 6:

RULE 6 — Status update at every session end:
  - Every session end produces an explicit status block answering:
    (1) project-wide — how many of 17 components shipped?
    (2) this session — what was completed?
    (3) pending — immediate next-session work + long-range remaining?
  - Goes in master doc, NEXT_CLAUDE_HANDOFF, AND the chat-message
    delivering the handoff zip — three places, one moment of
