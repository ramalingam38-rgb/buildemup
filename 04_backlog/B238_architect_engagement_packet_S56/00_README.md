## How to use this packet

**Week 1 (this week, S56):** Read `01_sourcing_channels.md` and `02_screening_criteria.md`. Build a candidate longlist of 8-12 architects. Send the outreach message from `03_outreach_message_template.md` to all of them.

**Week 2 (after replies):** Triage replies, run the vetting questions on shortlist of 3-4. Pick one. Sign a simple engagement letter using `05_compensation_structure.md` and `08_nda_and_data_handling.md` as terms.

**Week 3-4 (review window):** Send `06_briefing_pack_reading_list.md` and `07_review_question_template.md` to the chosen architect. Pay milestone 1. Schedule a 60-min mid-review call.

**Week 5 (debrief):** Receive written deliverable. Pay milestone 2. Use `09_feedback_intake_protocol.md` to log every finding as a new backlog item, tagged by which S55 LOCK it validates or refines.

## Why this matters

The S55-pinned LOCK baselines for C14/C15/C16 are defensible v1.0 candidates but they are **Claude-self-assessed**, not architect-validated. That distinction matters because:

1. The product exists to fix information asymmetry between Indian families and architects. If our product can't itself pass an architect's sniff test, the whole soul-statement is suspect.
2. NBC 2016 / TNCDBR / IS 962 / IS 6403 / IS 1904 citations in the code are referenced from training data, not from primary-source PDFs (see `05_integrity_check/B150_PARTIAL_NBC_VERIFICATION_S54.md` and `B108_PARTIAL_NBC_VERIFICATION_S55.md`). An architect with actual NBC desk-copies and current TNCDBR amendment tracking can validate these in hours; Claude cannot.
3. 5-15 specific refinement items are expected to surface from the review. Filing those into Bucket B is the v1.0 finalization step — without it, "v1.0 LOCKED" is provisional.

The packet is designed so that Ramalingam — a non-engineer founder — can run the engagement end-to-end without re-deriving the structure each step.
